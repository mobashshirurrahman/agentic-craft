Module 1.1 • Core Concept

The Evolutionary Leap to Agentic AI

From Passive to Active
💻

1. Traditional Code

deterministic: if/else, hardcoded logic

Rigid workflows. If an unforeseen edge case arrives, the program crashes with an unhandled exception.

🚫 Zero Adaptability
💬

2. Raw LLMs (Chatbots)

passive: prompt in → text out

Single-shot completion. Cannot execute code, check external APIs, or autonomously verify truth.

⚠️ Brain in a Jar
🤖

3. Autonomous Agent

goal-driven: perceive → act → verify

Maintains state, calls external tools, observes results, and re-plans until the high-level goal is achieved!

✅ Autonomous Agency
The Agent Formula: Agent = Reasoning Model (LLM) + Memory (State) + Tools (APIs) + Control Loop
Module 1.2 • Anatomy

The 4 Core Organs of an AI Agent

Cognitive Framework
👁️

1. Perception (Sensors)

Inputs

Converts raw environment signals into cognitive tokens: user prompts, tool returns, webhooks, and multimodal camera/audio feeds.

🧠

2. The Brain (Reasoning)

Cognition

The LLM core. Formulates plans, decomposes complex instructions, selects tools, and performs self-critique over intermediate failures.

🦾

3. Action (Effectors)

Tools

Executes side-effects: calling REST APIs, querying databases, running sandbox Python code, writing files, and dispatching webhooks.

💾

4. Memory (Persistence)

State

Maintains working context in RAM, durable state checkpoints in Postgres, and long-term semantic knowledge in vector stores.

Module 1.3 • Planning

Task Decomposition & Planning

Divide & Conquer
Decomposition Flow
🎯 High-Level Objective: "Launch Q3 Competitor Audit"
Step 1: Scrape Pricing Tool: search()
Step 2: Calculate Delta Tool: python()
Step 3: Compile Report LLM Synthesis

⚡ Single-Shot Fallacy

Asking an LLM to solve a 20-step engineering task in one prompt causes cognitive collapse. Planning turns complex goals into deterministic micro-steps.

🔄 Dynamic Re-Planning

If Step 2 encounters an unexpected 404 error, the agent doesn't crash — it updates the plan dynamically and switches to an alternate data source.

💡 Production Rule

Every sub-goal must produce a verifiable deliverable before downstream steps execute.

Module 1.5 • Tool Mechanics

How LLMs Call Real-World Tools

JSON Schema Contract
Step 1

Schema Definition

Developer registers Python function as JSON schema with argument types and docstring rules.

@tool def search(q: str):
Step 2

Model Tool Call

LLM decides to invoke tool. Emits structured JSON payload containing exact function name & kwargs.

{"name": "search", "q": "..."}
Step 3

Runtime Execution

Your application intercepts JSON, calls the real API / database, and captures return string.

result = search(q="...")
Step 4

Observation Ingestion

Observation string is appended to message history. LLM reads result and synthesizes the next answer!

ToolMessage(content="...")
📌 Golden Rule: The LLM never runs code itself — it produces structured JSON requests for your host runtime to execute!

Module 1.7 • Architecture Patterns

The Big 3 Agentic Design Patterns

ReAct • Plan-and-Solve • Reflection
⚡ Dynamic

1. ReAct Pattern

Reason → Act → Observe

Step-by-step interleaving. The agent thinks out loud before every single tool action. Best for open exploration and real-time search.

📋 Structured

2. Plan & Solve

Plan Ahead → Execute Batch

Planner agent produces an explicit N-step checklist. Worker agents execute each step sequentially. Cuts tool hallucinations by 40%.

🪞 Evaluative

3. Reflection (Critic)

Draft → Critique → Refine

Actor generates candidate response. Critic agent inspects output for logical flaws and forces iterative revisions before delivery.

Industry Standard: LangGraph and AutoGen blend ReAct execution inside structured Plan-and-Solve graphs!
Module 1.8 • State Retention

The 4 Agent Memory Architectures

Working vs Long-Term
💬

1. Short-Term Working Memory

RAM / Context

In-memory conversation history of the active session. Pruned automatically with token-aware windowing.

📌

2. Checkpoint State History

Postgres / Redis

Immutable snapshots saved at every graph node. Enables human-in-the-loop pausing and time-travel rewinds.

🔍

3. Semantic Memory (Vector DB)

pgvector / Pinecone

Long-term recall. Embeds previous conversations and user preferences for semantic nearest-neighbor retrieval.

📖

4. Episodic Memory

Audit Logs

Chronological log of past agent decisions: "Last Tuesday we tried scraping Site X and failed due to Cloudflare captcha."

💡 Rule of Thumb: Working memory handles the current turn; Checkpoints guarantee crash recovery; Vector stores provide years of context!
Module 1.9 • System Topology

Single-Agent vs Multi-Agent Systems

When to Scale

👤 Single Solo Agent

Simple & Fast
  • ✅ Easy to debug and trace in single terminal
  • ✅ Low latency and minimal token overhead
  • ❌ Suffers context bloat if given > 10 tools
  • ❌ Fails on conflicting roles (e.g. Creator vs Auditor)
Best for: Focused tasks with 1–5 tools (e.g. SQL query bot, customer FAQ router)

👥 Multi-Agent Swarm / Supervisor

Enterprise Grade
  • ✅ Isolated context windows per specialist
  • ✅ True parallel execution across sub-tasks
  • ✅ Natural adversarial critique and validation
  • ❌ Higher token costs and orchestration complexity
Best for: Complex workflows (e.g. Deep research, full-stack software development)
Architectural Heuristic: Start with 1 agent until tools exceed 8 or roles directly conflict!
Module 1.10 • Information Retrieval

Classic RAG vs Dynamic Agent Tools

Passive vs Active
📚 Read-Only

Classic RAG Pipeline

Embed → Vector Match → Inject → Answer

  • • Retrieves static text chunks from vector index
  • • Cannot verify whether the chunk is up to date
  • • Cannot trigger actions or mutate databases
  • • Fixed 1-shot pipeline: no retry if wrong chunk found
⚡ Read-Write-Verify

Agentic Tool Actions

Decide → Query → Inspect → Fallback

  • • Agent chooses WHEN to search and WHAT to query
  • • Evaluates if retrieved result is sufficient; re-queries if poor
  • • Executes live mutations: POST API calls, DB updates, sandboxes
  • • Full agency over multiple heterogenous data sources
💡 Agentic RAG: Wrap vector retrieval inside an agent tool — the agent can rewrite queries and verify relevance!

Module 1.12 • Failure Modes

The 5 Silent Killer Traps in Production

Hard-Won Lessons
1. The Infinite Tool Death Loop 🔁

A tool throws a 400 error. The agent re-runs the exact same command 100 times, burning $50 in API credits.

Fix: recursion_limit = 15 + circuit breaker
2. Tool Docstring Ambiguity 🌫️

Docstrings written in 5 seconds like "Searches data". The LLM hallucinates arguments and misroutes calls.

Fix: Explicit WHEN TO USE & WHEN NOT TO USE
3. Context Window Poisoning ☣️

Injecting 500-row raw SQL returns into state. Future turns suffer attention dilution and massive token costs.

Fix: Summarize or strip raw payloads after turn
4. Irreversible Side-Effects 💥

Allowing autonomous agents to execute destructive actions (DELETE SQL, sending emails) without human confirmation.

Fix: Human-in-the-loop interrupt breakpoints
Module 1.13 • Implementation

Anatomy of a Minimal Python Agent

Hands-on Skeleton
minimal_agent.py
LangGraph & LangChain 
from langgraph.prebuilt import create_react_agent
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def get_live_stock_quote(ticker: str) -> str:
    """Fetch live pricing. Use ONLY for current market quote requests."""
    return f"{ticker}: $182.40 (+1.4%)"

model = ChatOpenAI(model="gpt-4o", temperature=0.0)
tools = [get_live_stock_quote]

# Compiles cyclic state graph with model + tool-calling node:
agent = create_react_agent(model, tools)

response = agent.invoke({"messages": [("user", "What is Apple trading at?")]})
print(response["messages"][-1].content)
Lines of code: 14 lines Result: Fully autonomous tool-calling cognitive loop
Mastery Checklist

6 Golden Rules of Agentic AI

Level 1 Recap
✅

1. Agents are Not Chatbots

They possess sensory perception, external tools, memory state, and autonomous control loops.

✅

2. Tool Docstrings are Code

The LLM reads your docstrings to pick tools. Vague docstrings cause 90% of routing errors.

✅

3. Decompose Before Executing

Break high-level goals into small, verifiable sub-tasks rather than gambling on a single prompt.

✅

4. Keep Context Windows Trim

Strip raw tool dumps after synthesis; bloated context destroys attention and spikes costs.

✅

5. Always Set Circuit Breakers

Enforce maximum step limits (recursion_limit) and timeout caps on every autonomous run.

✅

6. Protect Dangerous Mutations

Use Human-in-the-Loop interrupts for destructive actions like payments, emails, and DB drops.
